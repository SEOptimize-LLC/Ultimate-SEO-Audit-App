# 2.3 / 2.4 / 3.1 — Optimize Target Pages (Refresh Log + per-page packet)

One shared tab ("2.3-3.1 Refresh Log") serves all three ClickUp tasks: one row
per refresh target, populated from the locked 1.8 plan, then worked through
the 9-step Refresh SOP. Piloted on EW 2026-08-20.

## The two-layer procedure

**Layer 1 — populate the log (scripted):**

    python scripts/fill_2_3.py <client> [--dry-run] [--force]

- Rows come from `Clients/<folder>/monthly_plan/plan.yaml` targets.
- **Baselines are copied VERBATIM from the client's 1.8 tab section A** — never
  recomputed — so the two tabs always reconcile. If a URL has no 1.8 match the
  script warns and leaves the baseline cells blank rather than inventing one.
- Column C carries the target queries plus the FULL refresh angle from the
  plan. The angle is where step-0 revision gates live ("page updated Aug 13 —
  pull that revision first"), so every row is self-contained.
- The script writes columns A:G only and refuses to overwrite real rows
  without `--force`. Snapshot taken before every write.

**Layer 2 — the per-page working packet (judgment, one page at a time):**

1. **Re-verify the row's facts live before starting.** The plan is days old by
   execution time. The EW pilot caught two supersessions this way: the
   "live duplicate" had been 301'd since the plan was written (family 7 → 6
   URLs), and the Aug 13 edit had already done the answer-first restructure.
2. **Intent check**: reuse the client's `gap_analysis/2026-08-serp-winners
   .json` when fresh (days old, not weeks); otherwise pull the live SERP.
   Name what the winners have that we lack.
3. **Rot scan**: fetch the live page, scan the article text for stale year
   references, dead prices, outdated screenshots. Report count, even if zero.
4. **Structure read**: headings via DFS `meta.htags`. Compare against the
   SOP's answer-first checklist — some pages arrive already restructured.
5. **Title + meta draft**: run through the recommendation-sanity-checker
   subagent BEFORE presenting. House rules BEAT the ClickUp SOP text where
   they conflict (see below).
6. **Schema check**: GSC URL Inspection (rich-results section). Works even
   when the site blocks our fetches.

## Checkpoint-column discipline (columns H onward)

The columns Outdated Cut → Date Done are **completion records: Y means
verified done, never assumed done.**

- Fill a checkpoint early ONLY with verified evidence, annotated: e.g.
  "Y - verified clean, nothing to cut (scan 2026-08-20)" or "Y - already in
  place per the page's Aug 13 update, verified live".
- Execution fields (Info Gain, Title+Meta, Outbound Links, Tracking, Live
  link, Date) stay blank until the work ships; when the owner reports a
  refresh live, re-verify against the live page before marking — same
  discipline as the 2.1 fix closes.
- Position Tracking is the owner's step even when the refresh is delegated.

## Standing rules and conflicts (resolved during the pilot)

- **Title budget**: the ClickUp SOP says "≤60 chars". The house rule wins:
  **65-character budget for the page-specific portion, brand suffix excluded
  from the count, no token (word/root/city) twice INCLUDING the suffix.**
  Flagged for template alignment; do not follow the ≤60 text.
- **EW-specific title constraint**: the brand contains the token
  "Walkthrough". EW currently serves titles without a suffix, but if the
  template ever appends "| Education Walkthrough", no visible title may
  contain "Walkthrough".
- **Meta descriptions may not promise what the page doesn't have yet.** A
  meta citing "downloadable checklist" ships WITH the refresh that adds the
  checklist, not before.
- No time estimates anywhere. Calendar language (recrawl windows) is fine.

## Client-specific fetch notes

- **EW**: direct fetches 403 (the owner's VPN IP is on the site's BlogVault
  blocklist). Route page reads through DFS `on_page/instant_pages`. Note:
  `raw_html` retrieval by task id does NOT work on instant fetches — use
  `meta.htags` for structure and `content_parsing/live` for body text.
